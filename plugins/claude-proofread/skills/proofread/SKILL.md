# Proofreading — report, never edit

Proofread what the user points at: a file, several files, or pasted text. If nothing is
named, ask which.

When asked to proofread, you *read* the prose and *report* on it. You do not touch the
file. Output is a list the author works through by hand; every item names the location
(file and line, or a short quoted fragment) so it can be found.

Three things to report, and nothing else:

**1. Mechanical errors.** Typos, missing or wrong articles (`a` / `an` / `the`), wrong
prepositions (`at` / `on` / `in` / `of` / `to`), subject–verb agreement, plurals, verb
tense, comma splices and missing commas, doubled or dropped words. For each one, state
the rule behind it in a sentence — the point is that the author stops making the mistake,
not that this one instance gets fixed. Treat each finding as a lesson: name the pattern
(e.g. "countable singular nouns need an article", "`depend` takes `on`, never `from`").

**2. Words the author is talking around.** When a sentence spends a clause describing
something a single word already covers, name that word and give its dictionary
definition, so the author's active vocabulary grows over time. Offer the word — do not
rewrite the sentence around it.

**3. Clutter, by William Zinsser's rules in *On Writing Well*.** Point at words that can
come out. Every finding must name the specific word or phrase and the principle it
violates — this is a closed checklist, not an invitation to comment on the writing in
general:

- *Clutter.* Words doing no work: `in order to` for `to`, `at this point in time` for
  `now`, `the reason why is that` for `because`, `referred to as` for `called`.
- *Qualifiers and hedges.* `very`, `quite`, `rather`, `a bit`, `sort of`, `kind of`,
  `pretty much`, `in a sense`. Zinsser's point is that they weaken the sentence they were
  meant to soften.
- *Adverbs that repeat the verb.* `blared loudly`, `gripped tightly` — the verb already
  says it. Same for adjectives that repeat the noun.
- *Long word where a short one exists.* `assistance`/`help`, `numerous`/`many`,
  `facilitate`/`ease`, `implement`/`do`, `utilize`/`use`, `initial`/`first`.
- *Nominalization.* A verb buried in an `-ion`/`-ment` noun — `made a decision` for
  `decided`, `performed an evaluation` for `evaluated`.
- *Passive voice* where an active verb would carry the sentence, unless there is no
  comfortable way around it.
- *Redundancy.* `personal friend`, `free gift`, `end result`, `completely eliminate`.
- *Over-explaining.* A sentence that restates what the previous one already established —
  Zinsser's "trust the reader".

Name the principle each time (e.g. "qualifier", "nominalization"), because these are
learnable as a set. Deleting is the author's call: flag the word, never lift it out.

Hard limits on this mode:
- No stylistic feedback beyond the Zinsser checklist above. That list is bounded on
  purpose — every item is a nameable rule with a word you can point at. Nothing about
  flow, tone, structure, pacing, or "this paragraph would be stronger if…".
- No rewritten sentences, not even as an illustration of a fix. Quote the broken fragment,
  name the error, state the rule. The author writes the correction.
- No edits to the file being proofread. Report only, even if the fix is a single missing
  comma and the author sounds impatient. If they want it applied, they will say so
  explicitly, and then it is a fix of exactly what was reported — nothing else in the
  file changes.
